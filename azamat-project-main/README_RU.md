# READABLE. — обновление вашего Streamlit-проекта

Готовый интерфейс по вашему эскизу: настройки слева, Original и Edited рядом,
шкала читаемости 0–100 и выборочное упрощение через Groq.
Оформление вдохновлено STACKED: терракотовый фон, кремовые панели, тёмные
кнопки и крупные заголовки. На узком экране панели располагаются друг под другом.

## Установка в существующий проект

Это **обновление**, которое использует ваши NLP-модули. Оно не заменяет
исследовательскую модель новой формулой.

1. Сделайте копию текущего `app.py`.
2. Скопируйте содержимое архива в корень вашего проекта — рядом с папкой `src`.
   Замените `app.py`. Добавьте папку `readable`, `requirements-web.txt` и этот README.
   Если `.streamlit/config.toml` уже существует, объедините настройки темы вручную.
3. Оставьте существующие `src/parsers.py`, `src/features.py`, `src/normalize.py`
   и их зависимости. **`features.py` не был приложен к запросу**, поэтому его нет
   в архиве: используется именно файл из вашего проекта.
4. В терминале VS Code, в активном окружении вашего проекта, выполните:

```powershell
python -m pip install -r requirements-web.txt
python -m streamlit run app.py
```

Требуется Python 3.10+. Зависимости интерфейса закреплены на проверенных версиях:
Streamlit 1.64.0, Groq SDK 0.37.1. Существующие зависимости NLP не переустанавливаются.

Если модели ещё не скачаны, установите spaCy/Stanza в окружение проекта, затем:

```powershell
python -m spacy download en_core_web_sm
python -c "import stanza; stanza.download('ru', processors='tokenize,pos,lemma,depparse'); stanza.download('kk', processors='tokenize,pos,lemma,depparse')"
```

Используется тот же набор процессоров, что в вашем `ParserManager`.
Если установка конкретной модели требует дополнительных процессоров, следуйте
сообщению установленной версии Stanza. После установки модели перезапустите приложение.

## Настройка Groq

Для своего локального запуска можно ввести ключ в закрытом поле
«Настройки ИИ». Он остаётся в памяти сессии и не записывается в исходники.
Для сайта, которым пользуется ваша аудитория, настройте ключ на сервере —
посетителям не понадобится создавать свой ключ.

Вариант для PowerShell:

```powershell
$env:GROQ_API_KEY="ваш_ключ"
python -m streamlit run app.py
```

Или создайте локальный `.streamlit/secrets.toml`:

```toml
GROQ_API_KEY = "ваш_ключ"
GROQ_MODEL = "llama-3.3-70b-versatile"
```

Не включайте этот файл в Git. При необходимости `GROQ_MODEL` можно изменить
на доступную вашему аккаунту текстовую модель с поддержкой JSON Object Mode.
Ключ нужен только для упрощения. Расчёт оценок работает локально.

## Как работает выбор предложений

- 0 — очень сложно; 100 — очень легко.
- X — **порог отбора**, а не обещанная оценка готового текста.
- При X = 40 выбираются предложения с оценкой **≤ 40**, включая ровно 40.
- X = 0 выбирает только предложения с оценкой 0. X = 100 выбирает все.
- При изменении X обновляется выделение. Новый запрос к ИИ выполняется только
  при нажатии «Упростить». Движение ползунка не запускает NLP или API.
- «Анализировать» разбирает весь исходный текст один раз и оценивает каждое
  предложение через ваш `calculate_readability_score(features, lang)`.
- В Groq отправляются **только выбранные предложения**, по шесть или меньше
  и суммарно до 6 000 символов в пакете. Сначала обрабатываются самые сложные.
- Числовые ID связывают ответы с точными позициями оригинала. Полный Edited
  собирается по этим позициям. Повторы одного предложения не перепутываются.
- Всё между заменами сохраняется точно: пробелы, переносы строк, абзацы, табуляция.
  Внутри заменённого предложения формулировка и разбивка могут измениться.
- Изменение текста или языка сбрасывает устаревший результат. Изменение X
  скрывает результат прошлого порога до следующего нажатия «Упростить».
- Кэш проверенных замен действует внутри одной сессии. Повторный запуск
  использует подходящие готовые замены. Результат всегда собирается из оригинала,
  без накопительного перефразирования уже изменённого текста.

## Проверка перефраза и ограничения

Модель получает ориентир `min(100, X + 15)`. Это пожелание, а не гарантия.
Кандидат повторно оценивается вашей локальной моделью и принимается только
при увеличении оценки. Если он разбит на несколько предложений, **каждое**
из них должно иметь оценку выше исходной; в таблице показывается минимум.
При исходной оценке 100 улучшение по этой шкале невозможно, поэтому вариант
не будет принят. Принятый вариант может остаться ниже X — автоматического
цикла повторных запросов нет.

Пропущенный/пустой ответ, неверный JSON, изменённые числа/ссылки/цитирования,
неулучшившаяся оценка и ошибка API сохраняют исходное предложение.
Если поздний пакет завершился ошибкой, успешные предыдущие замены сохраняются.
Причины видны в разделе «Оценки и изменения по предложениям».
Проверки не доказывают смысловую эквивалентность: имена, отрицания, причинные
связи и точность учебного содержания стоит просмотреть человеку.

Лимит исходного текста — 30 000 символов. Отдельное предложение длиннее
6 000 символов сохраняется с пояснением: приложение не обрезает его молча.
При первом обращении к языку загрузка NLP-модели может занять время.

## Важное про вашу формулу и примеры

В приложенном `normalize.py` к результату прибавляется `MEAN_ERRORS[lang]`:
10.9 для en, 20.7 для ru, 25.6 для kk. Поэтому с нынешней формулой нижняя
граница фактически выше 0, а часть высоких оценок обрезается до 100.
Это поведение сохранено. Например, при X = 20 ваш русский текст никогда
не будет выбран. Если вам принципиально нужен достижимый диапазон от 0,
пересмотрите калибровку отдельно: средняя ошибка сама по себе не является
обоснованной поправкой к каждому предсказанию. Для такой поправки нужна
проверенная направленная систематическая ошибка на валидационной выборке.

Примеры 0/20/40/60/80/100 показывают одну мысль в разных формулировках на
выбранном языке. Они подписаны как **условные ориентиры**, а не как измеренные
оценки модели. Точно приписывать фразе 20 или 80 без расчёта и калибровки было
бы некорректно. Примеры хранятся в `readable/examples.py` и не вызывают API.

## Файлы

| Файл | Назначение |
|---|---|
| `app.py` | Интерфейс, состояние сессии, кнопки и интеграция |
| `readable/core.py` | Отбор, пакеты, проверка ответа, кэш и сборка текста |
| `readable/nlp.py` | Адаптер к вашим трём NLP-модулям |
| `readable/provider.py` | Вызов Groq с JSON и безопасная обработка ошибок |
| `readable/examples.py` | Примеры уровней на трёх языках |
| `readable/assets/style.css` | Оформление |
| `tests/` | Проверки выбора, восстановления текста и интерфейса |

Контракт интеграции: `extract_features(doc, lang)` возвращает одну запись
на каждое `doc.sentences` в том же порядке. `Sentence.text` должен точно
соответствовать фрагменту оригинала. При несовпадении приложение останавливает
обработку вместо рискованной замены.

## Проверка

```powershell
python -m unittest discover -s tests -v
```

Тесты транспорта используют подставные ответы и не тратят API-запросы.
В среде подготовки пройдены 22 теста, включая четыре проверки интерфейса
через Streamlit AppTest. Проверены точное равенство X, крайние пороги,
повторяющиеся предложения, переносы строк, кэш, ошибки и смена текста/языка.
Интерфейс запускается без исключений. Визуальная проверка работающего
локального приложения через удалённый браузер в этой среде недоступна.
Полный запуск с вашей моделью требует отсутствовавшего в приложениях
`src/features.py`, установленных языковых моделей и вашего Groq key.

Документация использованных API:
[Streamlit cache_resource](https://docs.streamlit.io/develop/api-reference/caching-and-state/st.cache_resource),
[Groq Structured Outputs / JSON Object Mode](https://console.groq.com/docs/structured-outputs).
